# ATMOSLAM: исправление пустых пресетов и отсутствия звука на GitHub Pages

## Почему это произошло

Проект использует Vite, npm-модули, MIDI-воркер и **три AudioWorklet**.
Сайт **нельзя** публиковать напрямую из корня ветки `main` / `master` как готовые статические HTML/JS-файлы. Нужно сначала выполнить `npm ci` и `npm run build`, и публиковать **только папку `dist`**. Это автоматически делает включённый GitHub Actions workflow.

Когда `index.html` размещён напрямую, в нём остаётся ссылка `./src/main.js` и импорты вида `?worker&url`, которые браузер без Vite не умеет правильно обрабатывать. Из-за ошибки инициализации кнопки, пресеты и звук не работают.

## Исправление в браузере, без Node.js на вашем ПК

1. Загрузите **содержимое ZIP-архива**, а не ZIP целиком, в корень репозитория. При повторной загрузке замените одноимённые файлы.
2. На вкладке `Code` убедитесь, что существует **`.github/workflows/deploy.yml`**. Скрытая папка `.github` критична. Если её нет, создайте файл через `Add file → Create new file`, указав имя `.github/workflows/deploy.yml`, и вставьте содержимое одноимённого файла из архива.
3. Откройте `Settings → Pages → Build and deployment` и установите **Source: GitHub Actions**. НЕ `Deploy from a branch`.
4. Откройте `Actions → Build and publish ATMOSLAM (Vite)` и нажмите `Run workflow`, выбрав основную ветку репозитория (обычно `main`).
5. Убедитесь, что **оба задания** `build` и `deploy` завершились зелёной галочкой. Если какое-то задание красное, откройте его лог: сайт ещё не собран или не опубликован корректно.
6. Откройте адрес сайта из `Settings → Pages`. Обновите страницу через `Ctrl+Shift+R`. Нажмите `START AUDIO` (браузер разрешает звук только после действия пользователя).

## Как за 15 секунд понять, что опубликован нужный результат

Откройте исходный код **опубликованной страницы** (`Ctrl+U`, затем поиск `main.js`):

- **Неправильно:** `src="./src/main.js"` — опубликован исходный `index.html`, автоматическая сборка не была применена.
- **Правильно:** скрипт из `assets/index-<хеш>.js` или `/название-репозитория/assets/index-<хеш>.js` — Vite построил production-bundle.

При неверной публикации обновлённая версия также покажет в самом окне приложения красную диагностическую панель с инструкцией.

## Если `build`/`deploy` зелёные, но звук не появился

- Откройте `F12 → Console` и проверьте ошибки загрузки `.js`, `?worker`, AudioWorklet или 404.
- В `Network` проверьте, что JS/CSS/Worklet загружаются по адресу вида `/repository/assets/...`, а не `/assets/...` от корня GitHub.
- Убедитесь, что адрес начинается с `https://`.
- Нажмите на сайте `START AUDIO` после загрузки страницы.
- Если ошибка остаётся, пришлите URL сайта и первую красную ошибку из Console — это позволит проверить конкретный опубликованный сайт.

## Что содержит исправленный архив

- `.github/workflows/deploy.yml`: отдельные шаги `build` и `deploy`; рассчитан на **любую основную ветку**, а не только `main`; загружает в Pages только `dist`.
- `index.html` + `src/main.js`: заметная диагностика, если приложение не инициализировалось.
- `tests/pages-build.mjs`: проверяет рабочие JS/CSS-бандлы и наличие собранных AudioWorklet-скриптов.
- `tests/pages-boot.mjs`: проверяет диагностику неправильной публикации.
- Вся библиотека пресетов и звуковые DSP-движки остаются на месте.

## Ограничения проверки

Логика пресетов, UI-регуляторов и MIDI прошла доступные Node.js-тесты. Непосредственная `npm ci`/Vite production-сборка **не могла быть выполнена в среде сборки этого архива**: npm registry не разрешается через DNS. Рабочая сборка и публикация будут выполняться на GitHub Actions. Пока не увидим успешный `build` + `deploy` и результат в браузере, нельзя утверждать, что конкретный GitHub Pages-сайт исправлен.
