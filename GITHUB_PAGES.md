# ATMOSLAM · Generative Studio — GitHub Pages

Готовый проект для публикации на GitHub Pages. Содержимое архива нужно поместить **в корень репозитория**: `package.json`, `index.html`, `vite.config.js`, `src/`, `.github/workflows/deploy.yml`.

## Публикация без установки Node.js на Windows

1. Создайте репозиторий GitHub (например, `atmoslam-studio`). Для обычного бесплатного GitHub Pages рекомендуется **Public**; проверьте условия своего плана для приватных репозиториев.
2. Распакуйте ZIP. Загрузите **содержимое** папки проекта в репозиторий, а не сам ZIP и не вложенную папку проекта. Важно загрузить и скрытую папку `.github` с workflow.
3. Убедитесь, что файлы находятся в ветке `main` (workflow настроен на `main`).
4. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. В **Actions** дождитесь успешного выполнения **Deploy ATMOSLAM to GitHub Pages**. Если workflow не стартовал, выберите его и нажмите **Run workflow**.
6. Адрес для репозитория `atmoslam-studio` будет вида `https://USERNAME.github.io/atmoslam-studio/`; точный адрес показан в Settings → Pages и в Actions.

При каждом push в `main` сайт пересобирается и публикуется. `npm ci` и `npm run build` происходят **на серверах GitHub**; вашим посетителям Node.js не нужен.

## Важный момент: загрузка через GitHub UI

GitHub web upload может пропускать скрытые папки или загрузить не ту иерархию. Проверьте, что **`.github/workflows/deploy.yml`** виден в репозитории. Альтернативный способ — GitHub Desktop / git.

## Как работает путь к сайту

Workflow автоматически выбирает `PAGES_BASE_PATH`:

- `/<repo>/` — для обычных репозиториев `USERNAME.github.io/REPO/`;
- `/` — для репозитория `USERNAME.github.io`.

Пути к стилям, JS, AudioWorklet и Web Worker собираются Vite с правильным префиксом. Переименовывание репозитория требует нового деплоя. Для собственного домена с корнем `/` измените переменную `PAGES_BASE_PATH` в workflow на `/` (и настройте домен в GitHub Pages).

## Публикация исходников и данных

Если репозиторий публичный, исходный код и метаданные пресетов (включая названия анализированных аудиофайлов из каталога) тоже публичны. Исходные аудиосемплы в этом архиве не находятся. Не загружайте закрытые sample packs и персональные файлы в репозиторий.

## Возможности GitHub Pages

- Синтез звука выполняется в браузере через Web Audio API и AudioWorklet.
- Импорт аудио/MIDI-файлов происходит с устройства пользователя — их не нужно загружать в репозиторий.
- Настройки сохраняются в `localStorage` **того браузера и домена**, в котором открыт сайт; они не переносятся автоматически с localhost. Для переноса используйте Export/Import JSON.
- Запись и экспорт WAV выполняются локально в браузере с прежними ограничениями памяти и длительности.
- MIDI-устройства требуют разрешений и браузера с Web MIDI API; аппаратное MIDI не гарантировано на всех устройствах (обычно лучше Chrome/Edge на настольном ПК).
- GitHub Pages поддерживает HTTPS — необходимое условие для современного Web Audio и Web MIDI. Первый запуск звука всё равно должен быть инициирован нажатием кнопки пользователя.
- Это **статическое приложение**: нет серверного доступа к дискам пользователя, Windows-папкам `C:\...`, KICK 2, Python-анализатору или установленным VST. Генератор работает с локально выбранными файлами, но не получает автоматически доступ ко всему каталогу семплов.
- При недоступности Google Fonts используется запасной шрифт; синтез от этого не зависит.

## Если публикация не работает

- **404 на JS/CSS**: проверьте, что сайт опубликован именно через workflow и в `Actions` показана успешная сборка. Для нестандартного домена проверьте `PAGES_BASE_PATH`.
- **Workflow не виден**: файл `.github/workflows/deploy.yml` не попал в корень репозитория, или не разрешён запуск Actions.
- **Ошибка npm ci**: проверьте доступность npm registry в GitHub Actions и что `package-lock.json` сохранён без изменений.
- **Нет звука**: используйте `https://`, нажмите START AUDIO, проверьте разблокировку аудио браузером и консоль ошибок.
- **MIDI-устройство не найдено**: разрешите доступ к MIDI в браузере и попробуйте настольный Chrome/Edge.

## Локальная проверка

```sh
npm ci
npm run test:pages
npm run build
node tests/pages-build.mjs
npm run preview
```

Для имитации размещения в подкаталоге:

```sh
PAGES_BASE_PATH=/atmoslam-studio/ npm run build
PAGES_BASE_PATH=/atmoslam-studio/ node tests/pages-build.mjs
```

В PowerShell задайте переменную так: `$env:PAGES_BASE_PATH='/atmoslam-studio/'`.
