# diceFriend / RACK — обновление интерфейса

Новая интерфейсная оболочка для существующего проекта diceFriend Studio. Аудиодвижок, генераторы, MIDI-секвенсор, сэмплер, модули записи, эффекты и формат проекта не изменены.

## Для саунд-продюсера

- **AUDIO** — включить/выключить выбранный синтезатор (дублирует прежний START AUDIO).
- **PLAY** — запустить общий транспорт, синхронные пресеты и сэмплер (дублирует TRANSPORT START).
- **STOP** — остановить общий транспорт. При необходимости отдельно выключайте автономный синтезатор через AUDIO.
- **DICE** — случайная настройка из студийного DICE, с учётом разрешённых параметров и выбранного источника.
- **REC** — начать/остановить запись мастер-шины. После окончания экспорт WAV — в разделе MASTER.
- **BANK** — переключить активный пользовательский пресет прямо на сцене.
- **SYNTH** — выбор OS, три мультитач-площадки, 6 основных регуляторов и SHIFT для ещё 6.
- **SAMPLE** — локальный аудиофайл, воспроизведение и позиции, основные регуляторы и продвинутые эффекты.
- **MIDI** — загрузка/маршрутизация MIDI, треки, секвенсор и настройки.
- **MASTER** — уровни L/R, EQ, saturation, запись и экспорт.
- **PATCH LIBRARY** и **TRANSPORT / SYNC** свёрнуты по умолчанию; все функции сохранены.

### Почему две кнопки AUDIO и PLAY?

В исходном проекте это РАЗНЫЕ функции: AUDIO управляет выбранным синтезатором, PLAY — общим транспортом, который может запускать несколько источников. Объединение этих кнопок могло бы изменить музыкальное поведение проекта. Новый интерфейс сохраняет это различие.

### Зависимости / ограничения

- Chrome, Edge, Firefox и Safari последних версий. Для Web Audio требуется первое действие пользователя.
- Web MIDI зависит от браузера и устройства, на iPhone поддержка ограничена.
- На GitHub Pages нужно HTTPS (публикуется автоматически).
- Локальные пресеты хранятся в браузере; загрузить проект JSON можно через MASTER / EXPORT.
- Отрисовка и взаимодействие проверены в тестовой HTML-модели, но необходимо проверить работу аудио внутри Telegram и на реальных устройствах.

## Публикация на GitHub Pages — самая простая

1. Сделайте резервную копию действующего репозитория: **Code → Download ZIP**.
2. Распакуйте архив `dicefriend_rack_pages_upload.zip`.
3. Откройте `https://github.com/ufofamily/dicefriend/upload/main`.
4. Перетащите **содержимое** архива, включая `assets/`, `index.html`, `rack-ui.css`, `rack-ui.js` и `.nojekyll`.
5. Нажмите **Commit changes** и проверьте **Actions / Pages**.
6. Откройте `https://ufofamily.github.io/dicefriend/`, при необходимости обновите страницу без кеша (Ctrl+F5).

**Важно:** Не загружайте исходный ZIP как один файл в репозиторий и не помещайте `index.html` во вложенную папку. Старые файлы (`mobile-core.css`, `ui-mobile.js`, старые хешированные assets) можно удалить позже; новая версия их не использует.

Если у репозитория уже используется GitHub Actions с автоматической сборкой Vite, воспользуйтесь исходным архивом вместо готовых файлов и проверьте workflow, чтобы избежать конфликта схем публикации.

## Разработка из исходников

```bash
npm ci
npm run dev
npm run build
```

Папка `dist` после `npm run build` предназначена для GitHub Pages. Для локального просмотра и разработки нужен Node.js LTS, но для загрузки готового сайта он не требуется.

Основные файлы изменения: `public/rack-ui.css`, `public/rack-ui.js`, `index.html`. Звуковые исходники в `src/` оставлены без изменений.
